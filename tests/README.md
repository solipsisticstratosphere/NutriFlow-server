# NutriFlow API — Тести

Усі тести знаходяться в цій папці та запускаються проти локального сервера на порту 5000 (крім workflow-тесту — він використовує порт 5001).

## Важливо: захист основної бази даних

`npm run db:reset` та workflow-тест завжди підключаються до `TEST_MONGODB_URI` (`nutriflow-test`), а не до основної `MONGODB_URI`. Якщо `TEST_MONGODB_URI` не задано в `.env` — команда завершиться з помилкою.

## Перед запуском

```bash
# 1. Скинути тестову БД
npm run db:reset

# 2. Запустити основний сервер
npm start
```

## Список тестів

### test-api.js — повне тестування API
```bash
npm run test:api
```

Перевіряє всі основні endpoints:
- Root endpoint та Swagger
- Авторизація: реєстрація, логін, захищені роути, JWT-блок без токена
- Продукти: CRUD, пагінація, пошук, оновлення
- Прийоми їжі: створення з розрахунком КБЖУ, фільтрація за датою
- Обробка помилок: 400, 401, 404
- Performance: запит пагінації < 500ms
- Rate limiting: блок після 100 запитів/15 хв

**Результат:** 35/35 (100%)

---

### test-water-tracking.js — відстеження води
```bash
npm run test:water
```

- Отримання поточного денного логу
- Оновлення споживання води: 500 → 1500 → 2200 мл
- Комбіноване оновлення: вода + вага + нотатки
- Валідація: відхилення значень > 10 000 мл

**Результат:** 100%

---

### test-validation-direct.js — валідація
```bash
npm run test:validation
```

- Валідна вода (2000 мл) → 200 OK
- Вода 15 000 мл → 400 з описом помилки
- Вода -100 мл → 400
- Вага 600 кг → 400

**Результат:** 100%

### test-cache.js — AI кешування
```bash
npm run test:cache
```

Демонструє продуктивність кешу:
- 1-й запит: ~500–2000 мс (реальний виклик Groq API)
- 2-й запит: ~50–150 мс (з кешу, **~98% швидше**)

**Результат:** 100%

---

### test-ai.js — AI розпізнавання продуктів
```bash
npm run test:ai
```

- Розпізнавання продукту за назвою (`/ai/recognize-product`)
- Кешування: повторний запит значно швидший
- Створення продукту через AI (`/ai/create-product`) з коректною назвою
- Розпізнавання різних продуктів
- Валідація: назва < 2 символів → 400
- AI rate limiter: 20 запитів/годину

**Результат:** 100%

### test-ai-suggestions.js — AI рекомендації
```bash
npm run test:ai-suggestions
```

Потребує заповненої БД (`npm run db:reset`). Логіниться як Олена та запитує персоналізовані рекомендації:
- Рекомендовані продукти
- Ідеї страв (breakfast / lunch / dinner / snack)
- Поради по водному балансу
- Побутові поради

**Результат:** 100%

### full-test.js — повний workflow (порт 5000)
```bash
npm run test:full
```

Комплексний тест без прямого доступу до БД:
- Валідація, авторизація, продукти, прийоми їжі
- Обробка помилок, performance, rate limiting

**Результат:** 35/35 (100%)

### full-workflow-test.js — E2E тест (порт 5001)
```bash
# Термінал 1
npm run test:server

# Термінал 2
npm run test:workflow
```

Повний end-to-end тест з прямим доступом до тестової БД:
1. Очищення `nutriflow-test`
2. Запуск seeder
3. Верифікація даних
4. Логін, створення продукту через AI
5. Створення прийому їжі з кількома продуктами
6. Отримання AI рекомендацій

Використовує **порт 5001** та **`nutriflow-test`** — основна БД не торкається.

## Troubleshooting

**Сервер не запущений:**
```
Error: connect ECONNREFUSED 127.0.0.1:5000
```
→ Запустіть: `npm start`

**Помилка логіну / користувач не знайдений:**
```
Login failed
```
→ Скиньте тестову БД: `npm run db:reset`

**AI timeout або rate limit:**
```
⚠️ AI recommendations timed out
❌ Ліміт AI запитів вичерпано
```
→ Перезапустіть сервер (скидає лічильник 20 запитів/год) або зачекайте годину.

**Порт зайнятий:**
```
Error: EADDRINUSE
```
```bash
# Windows
taskkill /F /IM node.exe

# Linux/Mac
pkill node
```
